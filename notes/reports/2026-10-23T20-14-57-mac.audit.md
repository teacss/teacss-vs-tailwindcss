This is the third official report and the first on a stable TeaCSS release. It measured:

## The seven questions

1. **Why not double?**
   - The warm teacss-rs engine spends 48 % of its profile in the facade's `generate`, which carries the native call.
   - In the Vite build, the warm engine (52 ms) is 20 % of the 258 ms the CSS adds. The top build frames are module compilation (10 %) and `generate` (7 %).
   - The remaining cost is spread across the plugin pipeline. The optimization cards issued with this report profile it.
   - Tailwind's build spends 19 % in lightningcss.
2. **Was it tuned?**
   - Every subject ran its published package with the entry its documentation gives.
   - The `-default` subjects took 0.98x (teacss-rs), 0.99x (teacss-ts) and 1.01x (Tailwind) the tuned build time.
   - The `-postcss`, `-rsbuild` and `-bun` subjects use each tool's own plugin for that pipeline.
   - Every TeaCSS subject ran with `TEACSS_ENGINE_STRICT=1`.
3. **Did it break limits?** No. The largest output is Tailwind's under Bun, 3.2 MB. Medians grow with the utility count in every tier.
4. **Did it error?** No.
   - A run with any error, timeout, fallback, or missing or duplicate native binary writes no record, and this record exists.
   - Every Rust TeaCSS sample loaded `teacss-engine.darwin-arm64.node`, in Node and in Bun. No TypeScript sample did.
5. **Does it reproduce?** Each of the 378 groups has 30 interleaved samples. The median IQR is 2.6 % of the median. The noisiest groups are Tailwind's warm and +10 engine at some cells (29 % to 31 %) and the TypeScript engine's +100 at 1 000 x 300 (28 %). None carries a headline.
6. **Does it matter?**
   - The build tier is what a user waits on. At the largest cell the CSS work adds 258 ms for teacss-rs, 558 ms for Tailwind and 846 ms for teacss-ts to a 233 ms Vite build.
   - In a 1 000-class project Tailwind is ahead by under 30 ms.
   - The dev tier is what a user waits on most often: 100 ms against Tailwind's 322 ms.
7. **Did it even happen?** Yes.
   - Every warm and build group produced one hash. The build hashes are `ee274f23…ef007` at 1 000 x 300 and `f4ea28ce…96d4` at 20 000 x 300, the values teacss-ts expected.
   - teacss-ts and teacss-rs produced byte-identical output in all 3 510 sample pairs across the five groups: 1 890 main, 810 default-config, and 270 each in postcss, rsbuild and bun.

## Limits of this run

- **One machine:** an Apple M2 Max with 12 cores, running macOS. The Linux cross-check has not run.
- **One corpus.** The community corpus still waits for the owner's repository list, so every number here comes from the generated paired corpus.
- **The Bun group** runs in the Bun runtime. Its baseline and absolute times compare runtimes as well as CSS tools; the deltas over its own baseline are the comparison.
- **The author of this benchmark also develops TeaCSS.** The method, the pair table and the raw samples are published, and the run is reproducible from a clean clone.

## Correction: NODE_ENV in the dev tier (2026-10-25)

The harness created each Vite plugin before Vite set `NODE_ENV`. `@teacss/vite` up to 0.9.2 read `NODE_ENV` at that point, so in this run its dev server ran in TeaCSS's build mode, which skips the dev-mode rule details that `vite dev` users get. That made the TypeScript engine's dev rounds too fast: on 0.9.1, setting `NODE_ENV=development` took its dev +10 at 20 000 x 300 from 244.7 to 312.6 ms. The Rust engine moved from 74.1 to 75.2 ms and Tailwind from 322.9 to 335.0 ms. Read this report's TypeScript-engine dev numbers as a lower bound. Spec revision 6 sets `NODE_ENV` the way the CLIs do.

## Correction: packages loaded outside the task (2026-10-25)

The Vite subject modules imported every tool package at the top. Each build here also loaded packages a user's `vite build` would not: `@teacss/postcss` for TeaCSS, and `@tailwindcss/postcss` with PostCSS for Tailwind. Each cold engine sample, which times the subject's import, also loaded Vite and both plugins. Spec v01.1 revision 7 loads only what the task uses. On the same machine, the cold engine samples dropped by 38 to 64 ms for every tool, and builds moved by less than the noise, TeaCSS's by 4 to 9 ms and Tailwind's by -1 to +5 ms at 1 000 utilities. Read this report's engine-cold numbers as including about 40 to 60 ms of loading that no user pays.
