# TeaCSS 0.9.0：TypeScript 引擎与 Rust 引擎差多少

**结论。** TeaCSS 0.9.0 里，Rust 引擎生成同样的 CSS，产物逐字节相同，比 TypeScript 引擎快 3 到 9 倍，CPU 少用 3.3 倍，常驻内存少 42%。落到用户真正等待的地方，差距会变小，因为引擎只是整条链路的一段：

- 开发服务器里保存一个文件，快 2.6 倍；
- Vite 生产构建，快 2.2 倍；
- 在 1 000 个类的小项目里，构建只快 80 ms 左右。

代价有两项：

- 装包时多一个 8.4 MB 的原生文件；
- 第一次载入，在全新进程里约 1.1 ms。

装包这一项两种引擎都要付：`@teacss/vite` 直接依赖引擎，选 TypeScript 引擎也会装上同一个原生包。

## 一张表看完

20 000 个类、分在 300 个文件里，每格 30 次交替运行的中位数，方括号里是四分位范围：

| 场景 | TypeScript 引擎 | Rust 引擎 | Rust 快多少 |
| --- | --- | --- | --- |
| 在已经启动的进程里生成全部 CSS | 465 ms [456–477] | 52 ms [51–53] | 9.0 倍 |
| 全新进程，从启动到生成完 | 701 ms [696–717] | 154 ms [153–156] | 4.6 倍 |
| 往运行中的引擎里加 10 个类 | 105 ms [103–114] | 17 ms [16–17] | 6.3 倍 |
| 开发服务器里保存一个带 10 个新类的文件 | 261 ms [257–266] | 100 ms [99–102] | 2.6 倍 |
| Vite 生产构建 | 1.08 s [1.07–1.09] | 492 ms [489–496] | 2.2 倍 |
| 一次生成用掉的 CPU | 655 ms | 196 ms | 3.3 倍 |
| 生成后的常驻内存 | 670 MB | 391 MB | 少 42% |
| 产出的 CSS | 1 058 KB | 1 058 KB | 逐字节相同 |

## 换一个构建工具

两种引擎用的是同一个插件，差别只在引擎。下表是 CSS 给各构建工具增加的时间：从构建总时间里减去同一工具不带 CSS 工具时的基线，20 000 × 300。

| 构建工具 | 基线 | TypeScript 引擎 | Rust 引擎 | Rust 省下 |
| --- | --- | --- | --- | --- |
| Vite | 233 ms | +846 ms | +258 ms | 70% |
| Vite + PostCSS 插件 | 233 ms | +917 ms | +291 ms | 68% |
| Rsbuild | 224 ms | +968 ms | +314 ms | 68% |
| Bun（Bun 运行时） | 97 ms | +537 ms | +153 ms | 72% |

在每一种接法里，Rust 引擎都把 CSS 的成本砍掉约 70%。

## 规模越大，差距越大

| 场景 | 1 000 个类 | 5 000 个类 | 20 000 个类 |
| --- | --- | --- | --- |
| 已启动进程里生成：TS / Rust | 39 / 7 ms | 122 / 15 ms | 465 / 52 ms |
| 加 10 个类：TS / Rust | 6 / 1 ms | 24 / 4 ms | 105 / 17 ms |
| 开发服务器保存：TS / Rust | 57 / 37 ms | 101 / 54 ms | 261 / 100 ms |
| Vite 构建增加的时间：TS / Rust | +211 / +129 ms | +361 / +159 ms | +846 / +258 ms |

小项目里两种引擎都快，差距只有几十毫秒。到 20 000 个类，TypeScript 引擎加 10 个类要 105 ms，已经能感觉到；Rust 引擎是 17 ms。

## 对 Rust 不利的地方

- **构建里，引擎只占一部分。** 在已启动的进程里生成 20 000 个类只要 52 ms，但 Vite 构建里 CSS 一共要加 258 ms，引擎只占约 20%。其余是插件流水线：
  - 每个模块一次的提取与更新；
  - 模块加载；
  - lightningcss 压缩；
  - 字体 URL 改写。

  所以引擎快 9 倍，构建只快 2.2 倍。
- **原生文件不小。** 本机平台的 `.node` 文件 8.4 MB，共发布 8 个平台包。Tailwind 的 Oxide 是 2.8 MB、12 个平台包。
- **小项目收益有限。** 1 000 个类时，Vite 构建快 82 ms，开发服务器保存快 20 ms。
- **能服务的配置。** Rust 引擎服务了 teacss-ts 自带的 6 个示例配置中的 6 个。真实项目里如果用到它不支持的配置，`@teacss/core` 会退回 TypeScript 引擎。本次测试开着 `TEACSS_ENGINE_STRICT=1`，一旦退回就判整轮无效，所以表里每个 Rust 数字都确实来自 Rust。

## 怎么测的

- **对象。** npm 上发布的 TeaCSS 0.9.0：`@teacss/core`、`@teacss/vite`、`@teacss/postcss`、`@teacss/rsbuild`、`@teacss/bun`、`@teacss/preset-standard`，以及 `@teacss/engine` 0.9.0。两种引擎用同一套包，只用 `engine: "ts"` 与 `engine: "rust"` 或 `TEACSS_ENGINE` 切换。
- **语料。** 同一份按种子生成的语料：20 010 个工具类，覆盖内边距、外边距、颜色、尺寸等族，以及悬停、聚焦、首子元素、断点等条件。另有 1 000 和 5 000 两档，以及 3、30、300 个文件三种分布。
- **运行。** 每次测量一个全新进程。所有对象逐轮随机交替，每格 30 次。机器一分钟负载连续两分钟低于 2.4 才开始计时；本轮各格的负载份额在 18% 到 42% 之间。
- **计时。**
  - 引擎层：在进程里围绕一次生成调用计时，三次不计时的预热之后取样。
  - 开发服务器层：从写入新文件，到样式表第一次包含全部新类，每 5 ms 轮询一次。
  - 构建层：从进程启动到构建返回，不含基准程序自己的哈希、压缩与计数（规格 v01.1 修订 4）。
- **统计。** 报中位数与四分位范围。两组差距小于较大的四分位距、或 Mann-Whitney 检验 p ≥ 0.01，就写「无可测差异」。本轮 117 组 Rust 与 TypeScript 的直接对比全部是可测差异，Rust 都更快：113 组的 Cliff's delta 为 -1.00，也就是两组样本没有一个重叠；最弱的一组是 -0.96。
- **产物相同的证明。** 计时之前，每个对象在 9 种语料与文件分布上都先做一遍逐类校验：78 000 个用例，零差异。计时中，两种引擎在五个组的 3 510 对样本里产出逐字节相同，构建哈希是 `ee274f23…`（1 000 × 300）与 `f4ea28ce…`（20 000 × 300）。

## 公平性核对

逐条对照 teacss-ts 的 `notes/plans/perf-iteration-loop.md` §2：

| 要求 | 本文 |
| --- | --- |
| 做同样的工作并校验产物 | 同一套包、同一份语料，产物逐字节相同；错误计数为零 |
| 按生产方式运行 | 发布版、生产配置、同一个 Node 24.14.1；开箱默认配置另测，结论不变（构建时间是推荐配置的 0.98 与 0.99 倍） |
| 交替运行、多次取中位数、报范围 | 每格 30 次，逐轮随机交替；中位数与四分位范围见各表 |
| 负载门槛 | 负载连续两分钟低于 2.4 才开始计时；各格负载写在报告里 |
| 写出不利结果 | 见「对 Rust 不利的地方」 |
| 覆盖率与第二台机器 | 语料与配对表覆盖率见报告；Linux 交叉验证未跑，列为限制 |

## 限制

- 只有一台机器：Apple M2 Max，12 核，macOS。毫秒数在你的机器上会不同，比例一般能迁移。
- 只有生成的配对语料。来自真实 Tailwind 项目的社区语料还在等仓库清单。
- 本基准的作者也开发 TeaCSS。方法、配对表与原始样本全部公开，可以从干净的克隆复现。

## 自己复现

```bash
git clone https://github.com/teacss/teacss-vs-tailwindcss
```

```bash
cd teacss-vs-tailwindcss && git checkout e9a94c03 && bun install
```

```bash
bun run bench:verify --utilities 20000 --files 300 --group main,default-config,postcss,rsbuild,bun
```

```bash
bun run bench --group main,default-config,postcss,rsbuild,bun --out results
```

需要 Node 24.14.1 与 Bun 1.4.3；版本不对时，测量命令会拒绝运行。全量约 70 分钟。

每个数字都来自[第三份正式报告](../reports/2026-10-23T20-14-57-mac.md)和它的[原始记录](../../results/2026-10-23T20-14-57-mac.json)，审核见[这里](../reports/2026-10-23T20-14-57-mac.audit.md)。
