## What moved since 0.10.5

- **Every Node build lost about 73 ms, for every tool.** The Vite baseline went from 250 to 177 ms, the Rsbuild baseline from 246 to 177 ms. The Vite builds went from 388 to 314 ms (teacss-rs), 779 to 705 ms (Tailwind) and 1 043 to 969 ms (teacss-ts). What each tool adds to the baseline barely moved: +139 to +137, +529 to +528, +793 to +792 ms. This is what the eighth audit said: the Node binary sat in the baseline, not in the CSS share.
- **The build ratio grew.** teacss-rs against Tailwind went from 2.01x to 2.25x, close to the 2.2x the eighth audit estimated without the extra 70 ms.
- **A dev save with the Rust engine** went from 74 to 44.5 ms at 20 000 x 300, and from 81 to 53 ms for +100 classes. The dev tier is timed inside the running server, so the Node binary's start-up is not in it. teacss-ts (271 to 272 ms) and Tailwind (310 to 318 ms) did not move. The change is the `URL(` rewrite in `@teacss/vite` 0.10.7: before it released, teacss-rs measured 52 to 18 ms per dev stylesheet transform on Vite 8.3.5 at this cell, which is about the saving seen here.
- **`teacss build`** went from 340 to 200 ms at 20 000 x 300. About 70 ms of that is the Node binary, since the CLI starts through `#!/usr/bin/env node`. The rest is the teacss-rs releases since 0.10.5; this run does not say which one. `teacss-cli` went from 2 778 to 2 582 ms.
- **Tailwind's warm engine** went from 226 to 245 ms (+8 %), with the same Tailwind. Its +10 classes went from 116 to 119 ms. The warm tier is timed inside one process, so start-up is not in it. The TeaCSS engines moved by 2 % or less. The only change on Tailwind's side is the Node binary, so the official build runs Tailwind's JavaScript about 8 % slower than Homebrew's did. That is an inference; this run did not profile it. Every subject used the same binary, so it favours no tool against another in this run.
- **The Rust engine's resident memory** after a warm generation went from 294 to 337 MB. Its JavaScript heap is 39 MB, so most of the rise is outside the heap.

## The Node binary

The run script puts the official binary first on `PATH` and refuses to start if `node` resolves to anything else. The CLIs start through `#!/usr/bin/env node`, so they get the same binary. Its `node -e 0` takes about 60 ms on this machine against about 160 ms for the Homebrew binary, median of 5 each, timed with `/usr/bin/time`. The record names the Node version only, not the binary, so this audit is where the binary is stated.

## Where Tailwind wins

Against teacss-rs, nowhere in this run. At 1 000 utilities teacss-rs builds faster than Tailwind in all 15 tables, by 24 ms to 50 ms.

Against teacss-ts, Tailwind builds faster in all 18 build comparisons and generates faster in 18 of the 36 engine comparisons, with no measurable difference in the other 18. In the dev server teacss-ts is faster in 20 of 36 comparisons, Tailwind in 6, and 10 show no measurable difference.

## The seven questions

1. **Why not double?** The warm teacss-rs engine (43 ms) is 31 % of the 137 ms the CSS adds to a Vite build. The rest is the plugin pipeline.
2. **Was it tuned?**
   - Every subject ran its published package with the entry its documentation gives.
   - Every Node subject had what the CLIs set, and loaded only what its task needs.
   - With each tool's out-of-the-box entry instead, the build takes 0.96x as long for teacss-rs, 1.00x for teacss-ts and 1.01x for Tailwind.
3. **Did it break limits?** No. The largest output is Tailwind's default-configuration dev sheet, 4.6 MB.
4. **Did it error?** No. A run with any error, timeout, missing or duplicate native binary, or a cell over the load limit writes no record, and this record exists.
5. **Does it reproduce?** Each of the 369 groups has 30 interleaved samples. The median IQR is 3.4 %, against 4.2 % in the eighth report.
6. **Does it matter?**
   - A dev save takes 44.5 ms with the Rust engine, 272 ms with the TypeScript engine and 318 ms with Tailwind.
   - At the largest cell, the CSS work adds 137 ms for teacss-rs, 528 ms for Tailwind and 792 ms for teacss-ts to a 177 ms Vite build.
7. **Did it even happen?** Yes.
   - Every warm and build group produced one hash, 180 groups in all. The build hashes at 300 files are `37147c53…` (1 000 utilities), `f9a21fdc…` (5 000) and `3ea1defe…` (20 000), the same as in the eighth report.
   - teacss-ts and teacss-rs produced byte-identical output in all 810 engine and build sample pairs, and in all 18 dev-server groups.

## Limits of this run

- **One machine:** an Apple M2 Max with 12 cores, running macOS. The Linux cross-check has not run.
- **Absolute times do not compare with the eighth report**, because the Node binary changed. The deltas over each baseline do.
- **One corpus.** The community corpus still waits for the owner's repository list.
- **The Bun group** runs in the Bun runtime, with neither the compile cache nor `NODE_ENV`. The deltas over its own baseline are the comparison.
- **The CLI group** has no Tailwind subject.
- **The author of this benchmark also develops TeaCSS.** The method, the pair table and the raw samples are published, and the run is reproducible from a clean clone.
