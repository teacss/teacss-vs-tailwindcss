This is the eighth official report and the first one of TeaCSS 0.10. It measures, under spec v01.1 revision 10:

- teacss-rs 0.10.5 (`@teacss/engine`, `@teacss/vite`, `@teacss/postcss`, `@teacss/rsbuild`, `@teacss/bun`, `teacss`) and teacss-ts 0.10.5 (`@teacss/core`, `@teacss/preset-standard`, `@teacss/vite-ts`, `@teacss/cli`), two ecosystems that share no package ([ADR-0005](../adrs/ADR-0005-two-teacss-ecosystems.md));

- Vite 8.3.4, Rsbuild 2.2.14 and Bun 1.4.4, on Node 26.12.0;
- six groups (main, default configuration, PostCSS, Rsbuild, Bun, CLI) and the price section.

What changed since [the seventh report](2026-10-25T12-05-32-mac.md):

- **TeaCSS 0.10 has no engine switch.** Each ecosystem runs only its own engine, and the loaded native modules prove which one ran. teacss-ts publishes no PostCSS, Rsbuild or Bun integration, so those groups have one TeaCSS subject, on the Rust engine.
- **The CLI group is new.** It times `teacss-cli` (teacss-ts) against `teacss build` (teacss-rs). Tailwind's CLI is not in it.
- **Node 24.14.1 became Node 26.12.0**, because the teacss-rs packages need Node 26, and Bun 1.4.3 became 1.4.4. That moves every Node number, Tailwind's included, so milliseconds do not compare with earlier reports. See [the Node binary](#the-node-binary).

The record names commit `77120fa`, master at the time of the run, with nothing uncommitted.

## What TeaCSS 0.10 changed

The Node change confounds every comparison with the seventh report, so these are the movements large enough to stand out:

- **Adding classes to a running Rust engine** went from 18 ms to 6.2 ms at 20 000 x 300. Tailwind went from 140 to 116 ms in the same tier with the same version, which is the Node change.
- **The cold Rust engine** went from 103 to 55 ms: `@teacss/engine` no longer loads any of the TypeScript ecosystem.
- **The CSS share of a Rust-engine Vite build** went from 220 to 139 ms, while Tailwind's went from 574 to 529 ms.
- **Small projects.** In the seventh report Tailwind built measurably faster in 3 of the 15 tables at 1 000 utilities. Now teacss-rs is measurably faster in all 15, by 27 ms to 55 ms.

## The Node binary

The Vite baseline rose by about 75 ms in every cell, from 146–185 ms to 223–261 ms, with the same Vite. An A/B of one small Vite build, 12 alternating runs each with its own compile cache, gave a median of 107 ms on Node 24.12.0 and 180 ms on Node 26.12.0.

The cause is the binary, not Node 26. This run used Homebrew's Node 26.12.0, which links `libnode` and dozens of Homebrew libraries dynamically. An empty `node -e 0` takes 102 ms with it, 32 ms with the official Node 26.7.0 binary and 28 ms with Node 24.12.0. The compile cache works under it: the same build takes 198 ms without it.

Every Node subject pays this once per process: every build, both CLIs (each starts through `#!/usr/bin/env node`) and the cold engine process. So it favours no tool:

- The deltas over each baseline do not contain it.
- The build ratios are smaller than they would be with the official binary. Without the extra 70 ms or so, the Vite build ratio would be about 2.2x rather than 2.0x. This understates TeaCSS's lead, not Tailwind's.
- The Bun group does not run on Node.

A rerun on the official Node 26.12.0 binary would remove it. Until then, read the absolute build and CLI times as about 70 ms high.

## Where Tailwind wins

Nowhere in this run. At 1 000 utilities teacss-rs builds faster than Tailwind in all 15 tables. The TypeScript engine builds slower than Tailwind in all 18 build comparisons it is in.

## The seven questions

1. **Why not double?** The warm teacss-rs engine (42 ms) is 30 % of the 139 ms the CSS adds to a Vite build. The rest is the plugin pipeline.
2. **Was it tuned?**
   - Every subject ran its published package with the entry its documentation gives.
   - Every Node subject had what the CLIs set, and loaded only what its task needs.
   - With each tool's out-of-the-box entry instead, the build takes 0.97x as long for teacss-rs, 1.00x for teacss-ts and 1.01x for Tailwind.
3. **Did it break limits?** No. The largest output is Tailwind's default-configuration dev sheet, 4.6 MB.
4. **Did it error?** No. A run with any error, timeout, missing or duplicate native binary, or a cell over the load limit writes no record, and this record exists.
5. **Does it reproduce?** Each of the 369 groups has 30 interleaved samples, and the spread is below that of the seventh report.
6. **Does it matter?**
   - A dev save takes 74 ms with the Rust engine, 271 ms with the TypeScript engine and 311 ms with Tailwind.
   - At the largest cell, the CSS work adds 139 ms for teacss-rs, 529 ms for Tailwind and 793 ms for teacss-ts to a 250 ms Vite build.
7. **Did it even happen?** Yes.
   - Every warm and build group produced one hash, 180 groups in all. The build hashes at 300 files are `37147c53…` (1 000 utilities), `f9a21fdc…` (5 000) and `3ea1defe…` (20 000).
   - teacss-ts and teacss-rs produced byte-identical output in all 810 engine and build sample pairs.
   - The two dev servers serve sheets that differ by exactly 144 928 bytes in every cell. The difference is the four bundled fonts: `@teacss/vite` inlines them as data URIs and `@teacss/vite-ts` links them under `/__teacss_fonts/`. With each font reduced to its digest, the two sheets are the same. So `@teacss/vite` sends more bytes per dev response, which if anything costs it time.

The report generator used to explain any difference outside the engines with revision 9's Lightning CSS note. This round showed that the note no longer applies, so the generator now counts the Vite build and the dev server separately and names the fonts.

## Limits of this run

- **One machine:** an Apple M2 Max with 12 cores, running macOS. The Linux cross-check has not run.
- **The Homebrew Node binary** adds about 70 ms to every Node process; see above.
- **One corpus.** The community corpus still waits for the owner's repository list.
- **The Bun group** runs in the Bun runtime, with neither the compile cache nor `NODE_ENV`. The deltas over its own baseline are the comparison.
- **The CLI group** has no Tailwind subject.
- **The author of this benchmark also develops TeaCSS.** The method, the pair table and the raw samples are published, and the run is reproducible from a clean clone.
