# Audit of run 2026-10-25T07:25:49Z

This audit reviews [the report](2026-10-25T07-25-49-mac.md) against the benchmark checklist. The report is generated from [the raw record](../../results/2026-10-25T07-25-49-mac.json) by `bun run bench:report`, and it regenerates byte for byte. This audit is written by hand, so it is kept in a separate file.

This is the fifth official report. It measured:

- TeaCSS 0.9.3 from npm (`@teacss/core`, `vite`, `postcss`, `rsbuild`, `bun`, `preset-standard`), with `@teacss/engine` 0.9.3 pinned exactly by core;
- Tailwind CSS 4.3.3;
- Vite 8.3.4, Rsbuild 2.2.14 and Bun 1.4.3, on Node 24.14.1;
- all five groups (main, default-config, postcss, rsbuild, bun) and the price section.

It is the first report under spec v01.1 revision 5 and v02.1 revision 5. Those revisions give every Node build and dev subject Node's compile cache, as the `vite` and `rsbuild` CLIs turn it on; engine tasks and Bun subjects run without it. **Build and dev numbers in this report are not comparable with the earlier reports.** The engine tier is.

From 0.9.2 on, TeaCSS defaults to the Rust engine. Every TeaCSS subject here still names its engine (`engine: "ts"` or `"rust"`, or `TEACSS_ENGINE` for the PostCSS and Bun subjects), so the TypeScript-engine rows are the TypeScript engine. No TypeScript sample loaded the native file, and every Rust sample did.

The record names commit `a7b9000`, which is master before this report's pull request. The run used that tree plus the uncommitted pin of the TeaCSS packages to 0.9.3, which the pull request commits. To reproduce, check out the merge commit of that pull request.

## A regression in 0.9.3: the TypeScript engine's dev server

The TypeScript engine's dev rounds are slower in 0.9.3. At 20 000 x 300, dev +10 takes 301 ms, against 228 ms in the 0.9.1 report. The gap grows with the corpus: about 6 ms at 1 000 utilities, 15 ms at 5 000 and 70 ms at 20 000. The `-default` subject shows the same.

This is a change in TeaCSS, not in the harness:

- The compile cache of revision 5 is on before a dev server starts, and it does not touch the timed region inside the running server. teacss-rs's dev rounds (70.1 against 70.8 ms) and Tailwind's (320.6 against 324.8 ms) did not move.
- After this run, 0.9.1 and 0.9.3 alternated twice on the same harness, with 20 samples each. teacss-ts's dev +10 at 20 000 x 300 went from 231.3 to 307.2 ms (Cliff's delta -0.99), and at 5 000 x 300 from 94.0 to 110.8 ms. teacss-rs and Tailwind did not move.
- A single alternation of 0.9.2 and 0.9.3 gave 234.8 and 314.9 ms. The step is between 0.9.2 and 0.9.3, whose only change is the lazily loaded `@teacss/vite` entry (B6).

The TypeScript engine's engine tier did not slow down (warm 461 ms, +10 103 ms). Its resident memory after a warm generation is 782 MB, against 652 MB in the 0.9.1 report; that tier does not use the Vite plugin, so it may be a separate change. Both findings are with teacss-ts. A fix will be measured in the unreleased lane.

## The seven questions

1. **Why not double?**
   - The warm teacss-rs engine spends 49 % of its profile in the facade's `generate`.
   - In the Vite build, the warm engine (51 ms) is 23 % of the 222 ms the CSS adds. The top build frame is `generate` (8 %).
   - Tailwind's build spends 21 % in lightningcss.
2. **Was it tuned?**
   - Every subject ran its published package with the entry its documentation gives.
   - The `-default` subjects took 1.00x (teacss-rs), 1.01x (teacss-ts) and 1.00x (Tailwind) the tuned build time.
   - Every TeaCSS subject ran with `TEACSS_ENGINE_STRICT=1`.
3. **Did it break limits?** No. The largest output is Tailwind's under Bun, 3.2 MB. Medians grow with the utility count in every tier.
4. **Did it error?** No. A run with any error, timeout, fallback, or missing or duplicate native binary writes no record, and this record exists.
5. **Does it reproduce?**
   - Each of the 396 groups has 30 interleaved samples. The median IQR is 3.1 % of the median.
   - The noisiest groups are Tailwind's warm and +10 engine at some cells (22 % to 28 %), and the TypeScript engine's dev +100 at 1 000 utilities (20 % to 25 %).
   - None carries a headline.
6. **Does it matter?**
   - A dev save takes 71 ms with the Rust engine, 301 ms with the TypeScript engine and 325 ms with Tailwind.
   - At the largest cell, the CSS work adds 222 ms for teacss-rs, 564 ms for Tailwind and 818 ms for teacss-ts to a 178 ms Vite build.
   - In a 1 000-class project the two are within 15 ms either way.
7. **Did it even happen?** Yes.
   - Every warm and build group produced one hash. The build hashes are the same as in 0.9.0 and 0.9.1: `ee274f23…ef007` at 1 000 x 300 and `f4ea28ce…a96d4` at 20 000 x 300.
   - teacss-ts and teacss-rs produced byte-identical output in all 3 510 sample pairs across the five groups.

## Against the fourth official report (0.9.1, 2026-10-24)

The engine tier is comparable: its protocol did not change.

- teacss-rs: warm 51.3 → 51.0 ms, +10 17.1 → 16.3 ms, cold 157.9 → 146.1 ms.
- teacss-ts: warm 465.8 → 461 ms.
- Tailwind: warm 224.7 → 220 ms.

The build and dev tiers are not comparable, because revision 5 turned the compile cache on. The Vite baseline went from 234.8 to 177.6 ms, and Rsbuild's from 226.2 to 175.7 ms; the P14 lane, under revision 5 on the day before, already measured 182 ms for Vite, so nearly all of that is the cache.

The Bun baseline went from about 72 to 44 ms in every cell, although Bun subjects run without the cache. Every Bun subject moved by about the same amount (Tailwind -37 ms, teacss-rs -33 ms, teacss-ts -35 ms at 20 000 x 300). A check after the run measured the Bun baseline at 42 ms, and 44 ms with an empty temporary directory, so no cache explains it. The machine was restarted between the two runs, and Bun's process start is about 30 ms faster since. The cause is not isolated. It moves the Bun group's absolute times but not what each tool adds over its baseline.

Within this run, the Vite build's CSS cost is 222 ms for teacss-rs, against 245 ms in the 0.9.1 report, and 564 ms for Tailwind, against 575 ms. Those deltas subtract each round's own baseline, but the cache may also speed up each plugin's own modules, so they are not a clean comparison either.

The unreleased lane measured P14 (teacss-rs's faster extraction, not yet published) under revision 5 and found no measurable effect on any dev or build cell ([optimization cards](../knowledge/optimization-cards-2026-10-24.md)).

## Limits of this run

- **One machine:** an Apple M2 Max with 12 cores, running macOS. The Linux cross-check has not run.
- **One corpus.** The community corpus still waits for the owner's repository list.
- **The Bun group** runs in the Bun runtime, without the compile cache. Its baseline and absolute times compare runtimes as well as CSS tools; the deltas over its own baseline are the comparison.
- **The author of this benchmark also develops TeaCSS.** The method, the pair table and the raw samples are published, and the run is reproducible from a clean clone.
