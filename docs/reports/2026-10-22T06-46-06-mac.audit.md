## The seven questions

1. **Why not double?** The warm teacss-rs engine spends 70 % of its profile in the facade's `generate`, which carries the native call. In the teacss-rs build, `generate` is 18 % and module compilation 7 %; the warm engine (157 ms) is 36 % of the build's 440 ms delta over the baseline, and no single other frame dominates the rest. Tailwind's build spends 19 % in lightningcss. The `buildEnd` re-parsing that dominated the first report is gone, and so is the easing visitor that the [dev profile](../knowledge/teacss-vite-dev-profile-2026-10-22.md) found on the dev and build paths.
2. **Was it tuned?** Every subject ran its published package with its documented entry; the `-default` subjects ran the setup guide's entry and took 1.00x (teacss-rs), 0.98x (teacss-ts) and 1.01x (Tailwind) the tuned build time; the `-postcss` subjects ran each tool's PostCSS plugin. `TEACSS_ENGINE_STRICT=1` was set for every TeaCSS subject.
3. **Did it break limits?** No. The largest output is Tailwind's warm engine, 3.9 MB in 220 ms. Medians grow with the utility count in every tier.
4. **Did it error?** No. A run with any error, timeout, fallback, missing or duplicate native binary writes no record, and this record exists. Every teacss-rs sample loaded `teacss-engine.darwin-arm64.node` and no teacss-ts sample did.
5. **Does it reproduce?** Each of the 306 groups has 30 interleaved samples. The median IQR is 4.3 % of the median. The noisiest groups are small cells: Tailwind's +10 engine at 1 000 x 30 (31 %) and the dev tier at 1 000 utilities (27 %). The 11 pairs reported as "no measurable difference" are all teacss-rs against Tailwind or their twins: the warm engine at 1 000 utilities, the +10 engine at 5 000, the +100 dev round at 5 000, the default build at 1 000 x 3 and the PostCSS build at 5 000 x 300.
6. **Does it matter?** The build tier is what a user waits on. Its baseline is 281 ms of Vite with no CSS tool. At the largest cell the CSS work adds 440 ms for teacss-rs, 756 ms for Tailwind and 923 ms for teacss-ts.
7. **Did it even happen?** Yes. Every warm and build group produced one hash, every incremental and dev call matched the same call in the other processes and contained the classes it added, and the verification before timing covered 78 000 paired cases.

## Against the alpha.3 local run

The engine tiers did not move: warm teacss-rs 156 to 157 ms, warm teacss-ts 451 to 466 ms, Tailwind 220 to 220 ms; the Vite baseline 278 to 281 ms. Everything that changed is in the Vite plugin, between teacss-ts `e133aff1` and the published `d01a30dc`:

- **Dev tier.** teacss-rs 530 to 168 ms, teacss-ts 633 to 256 ms. The cause was the easing visitor running on every dev transform of the whole stylesheet; the fix hands TeaCSS's own stylesheet only the user's visitor. The dev clock is revision 4 here (it stops at the receipt of the first complete response), which explains Tailwind's 337 to 323 ms; the TeaCSS drop is the plugin.
- **Build tier.** teacss-rs 1 126 to 721 ms, teacss-ts 1 594 to 1 204 ms. The build's final minify had carried the same visitor.
- **PostCSS round**, measured for the first time: at 20 000 x 300, teacss-rs-postcss 897 ms, tailwind-v4-postcss 1 106 ms, teacss-ts-postcss 1 394 ms. TeaCSS's PostCSS plugin costs it 176 ms over its Vite plugin; Tailwind's costs 69 ms.
- **Price**, measured for the first time on published packages: the Rust engine's native file is 8.2 MB against Oxide's 2.8 MB, both load in about 1.2 ms, both tools install in about 3.2 s from an empty cache to about 43 MB, and the engine served all 6 example configurations it was given.

## Limits of this run

- **One machine.** An Apple M2 Max with 12 cores, running macOS. The CI cross-check has not run.
- **Community corpus.** The repository list is still pending, so this run uses the generated corpus only.
- **Installing @teacss/engine.** Its npm `latest` tag still points at 0.8.5-alpha.4; @teacss/core pins the exact version, and this repository's lockfile does too. Reproduce from the lockfile.
- **The author of this benchmark also develops TeaCSS.** The method, the pair table and the raw samples are published, and the run is reproducible from a clean clone.
