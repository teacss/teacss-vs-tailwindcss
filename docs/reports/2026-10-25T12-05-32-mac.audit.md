# Audit of run 2026-10-25T12:05:32Z

This audit reviews [the report](2026-10-25T12-05-32-mac.md) against the benchmark checklist. The report is generated from [the raw record](../../results/2026-10-25T12-05-32-mac.json) by `bun run bench:report`, and it regenerates byte for byte. This audit is written by hand, so it is kept in a separate file.

This is the seventh official report. It measures the same packages as [the sixth](2026-10-25T08-53-46-mac.md) under spec v01.1 revision 8:

- TeaCSS 0.9.3 from npm, with `@teacss/engine` 0.9.3 pinned exactly by core;
- Tailwind CSS 4.3.3;
- Vite 8.3.4, Rsbuild 2.2.14 and Bun 1.4.3, on Node 24.14.1;
- all five groups and the price section.

What revisions 7 and 8 changed:

- **Revision 7: each subject process loads only what its task uses.** Before it, every Vite build also loaded the other pipeline's plugin: `@teacss/postcss` for TeaCSS, and `@tailwindcss/postcss` with PostCSS for Tailwind. Every cold engine sample, which times the subject's import, also loaded Vite and both plugins.
- **Revision 8: a run writes no record when the load share at either end of any cell passes 50 %.** A revision 7 run on the same evening recorded 37 % to 108 % while another application kept the machine busy, and it was discarded.

Engine-cold and build numbers of revision 7 and later are not comparable with earlier reports. The record names commit `0a0a765`, master at the time of the run, with nothing uncommitted.

## The seven questions

1. **Why not double?** The warm teacss-rs engine (52 ms) is 24 % of the 220 ms the CSS adds to a Vite build. The rest is the plugin pipeline; the small-project cards name its fixed costs.
2. **Was it tuned?**
   - Every subject ran its published package with the entry its documentation gives.
   - Every subject had what the CLIs set, and loaded only what its task needs.
   - Every TeaCSS subject ran with `TEACSS_ENGINE_STRICT=1`.
3. **Did it break limits?** No. The largest output is Tailwind's under Bun, 3.2 MB.
4. **Did it error?** No. A run with any error, timeout, fallback, missing or duplicate native binary, or a cell over the load limit writes no record, and this record exists.
5. **Does it reproduce?** Each of the 396 groups has 30 interleaved samples. The noisiest are Tailwind's warm and +10 engine scenarios and the +100 scenarios at 1 000 utilities, none of which carries a headline.
6. **Does it matter?**
   - A dev save takes 77 ms with the Rust engine, 311 ms with the TypeScript engine and 324 ms with Tailwind.
   - At the largest cell, the CSS work adds 220 ms for teacss-rs, 574 ms for Tailwind and 831 ms for teacss-ts to a 185 ms Vite build.
7. **Did it even happen?** Yes.
   - Every warm and build group produced one hash. The build hashes are `ee274f23…ef007` and `f4ea28ce…a96d4`, as since 0.9.0.
   - teacss-ts and teacss-rs produced byte-identical output in all 3 510 sample pairs.

## Limits of this run

- **One machine:** an Apple M2 Max with 12 cores, running macOS. The Linux cross-check has not run.
- **One corpus.** The community corpus still waits for the owner's repository list.
- **The Bun group** runs in the Bun runtime, with neither the compile cache nor `NODE_ENV`. The deltas over its own baseline are the comparison.
- **The author of this benchmark also develops TeaCSS.** The method, the pair table and the raw samples are published, and the run is reproducible from a clean clone.
