## Fixed before this run

The local link initially gave TeaCSS an unfair handicap. The linked `@teacss/vite` resolved `vite` and `lightningcss` from the teacss-ts checkout's own `node_modules`. Every TeaCSS build process therefore loaded a second Vite, with rolldown, fsevents and lightningcss twice. A published install dedupes these, and the alpha.1 record shows each binary once.

The subject process now resolves those two packages to the benchmark's copies when the importer is outside this repository. Any response in which one package version loads its addon from two paths now fails. Every TeaCSS sample in this record lists each binary once. Tailwind loads lightningcss 1.32.0 and 1.33.0, which are two versions, and that is allowed.

## The seven questions

1. **Why not double?** The warm teacss-rs engine spends 70 % of its profile in the facade's `generate`. The profiler attributes the native call to that frame. The TeaCSS build profiles now share the shape of Tailwind's: lightningcss is the top frame (29 % for teacss-rs, 19 % for Tailwind) and `generate` takes 12 %. The `buildEnd` re-parsing that dominated the alpha.1 profile no longer shows among the top frames. The remaining gap to Tailwind is the lightningcss pass plus the engine.
2. **Was it tuned?** Each tool ran its documented production entry, and the `-default` subjects ran the setup guide's entry. TeaCSS ran the local build named above, and Tailwind ran published 4.3.3. `TEACSS_ENGINE_STRICT=1` was set for every TeaCSS subject. The default entries took 1.00x the time of the tuned ones for all three tools.
3. **Did it break limits?** No. The largest output is Tailwind's warm engine, 3.9 MB in 220 ms. Medians grow with the utility count in every tier.
4. **Did it error?** No. A run with any error, timeout, fallback or unexpected native binary writes no record, and this record exists. Every teacss-rs sample loaded `teacss-engine.darwin-arm64.node`, and no teacss-ts sample did.
5. **Does it reproduce?** Each of the 279 groups has 30 interleaved samples. The median IQR is 5.3 % of the median. The noisiest groups are the dev tier at 1 000 utilities, at 37 % to 43 %: about 100 ms rounds against the 5 ms polling step. Those cells carry no headline. The 15 pairs reported as "no measurable difference" are all teacss-rs against Tailwind, or their default-config twins: the warm engine at 1 000 utilities and at 20 000 in 30 files, the +10 incremental engine at 5 000 utilities, and the dev tier at 1 000 utilities.
6. **Does it matter?** The build tier is what a user waits on. Its baseline is 278 ms of Vite with no CSS tool. At the largest cell, the CSS work adds 754 ms for Tailwind, 848 ms for teacss-rs and 1 316 ms for teacss-ts.
7. **Did it even happen?** Yes. Every warm and build group produced one hash. Every incremental and dev call matched the same call in the other processes and contained the classes it added. The verification before timing checked 78 000 paired cases across 63 subject runs.

## Against the alpha.1 run

- **The build tier improved and the file-count effect is gone.** At 1 000 utilities, teacss-ts took 6.34x Tailwind's build time with 300 files in alpha.1. It now takes 1.50x with 3 files and 1.47x with 300. teacss-rs builds dropped from 1 748 ms to 1 126 ms at the largest cell, and teacss-ts builds from 3 750 ms to 1 594 ms.
- **Cross-run times are not directly comparable.** The alpha.1 run used Node 26.7.0, and this one uses the pinned 24.14.1. Tailwind's build moved from 820 ms to 1 032 ms with no change on its side, and the Vite baseline moved from 258 ms to 278 ms. Use the ratios within each run, not the milliseconds across runs.
- **The engine tiers did not move.** Warm teacss-rs took 155 ms and now takes 156 ms; warm teacss-ts took 446 ms and now takes 451 ms. The changes since alpha.1 are in the Vite plugin, not the engine.

## Limits of this run

- **No price section.** The price step installs each subject from the registry, and 0.9.0-alpha.3 is not published. The first attempt at this run failed at that step after the full timing and lost the record. `bench run` now skips the price step up front when any subject is linked, and says why.
- **No PostCSS round.** The link does not cover `@teacss/postcss`, so the `postcss` group was not run.
- **Load.** The run started after two quiet minutes below a load of 2.4. The load share recorded around each cell stayed between 20 % and 35 %.
- **One machine.** An Apple M2 Max with 12 cores, running macOS. The CI cross-check has not run.
- **The dev-tier clock included the harness's read of the final response.** Found after this run ([dev profile](../knowledge/teacss-vite-dev-profile-2026-10-22.md)): each dev sample ended after the harness had parsed the stylesheet module and checked the new classes, about 10 ms to 50 ms at 20 000 utilities and more for Tailwind's larger stylesheet, and stale polls parsed the module every time. The rankings do not change and the medians move within noise: a re-trace with the corrected harness moved Tailwind from 332 ms to 322 ms. Spec v02.1 revision 4 stops the clock at the receipt of the first complete response and reads an unchanged response once; dev-tier samples of this run (revision 3) are not comparable with later ones.
