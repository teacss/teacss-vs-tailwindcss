# ADR-0002: 成对语料与两级等价
Status: accepted

## Context
TeaCSS 写 `p:4@hover`，Tailwind 写 `hover:p-4`。共用一份 Tailwind 语法的语料会让 TeaCSS 对大部分输入「不认识即跳过」，量到的是跳过的速度。两边的设计系统调色板与单位不同，输出的值不可能逐字节相同，所以「输出相同」不能作为做了同样工作的判据。

## Decision
语料由带种子的生成器从一张配对表产出，每个用例同时给出两种写法并声明应产生的属性名集合与条件结构。等价分两级：teacss-ts 与 teacss-rs 的输出必须逐字节相同（强等价）；TeaCSS 与 Tailwind 对同一用例必须产出相同的属性名集合与条件结构，值不比较（结构等价）。配对表只收录两边都原生支持的属性族，表本身与每份语料的属性族分布随报告公开。

## Consequences
报告可以回答「两边做了同样的工作吗」，答案是「同样的属性与条件，值按各自设计系统」。配对表是报告可信度的一部分，任何人可以指出它偏向某一方并提交用例。代价是语料覆盖的属性族比任一工具的全集小。

## Alternatives considered
- 直接用 Tailwind 的语料跑 TeaCSS：见 Context。
- 让两边输出逐字节相同：要求改写一方的主题，测的就不再是发布的工具。
- 用真实项目作为语料：真实项目只用一种语法，无法配对；可作为第二阶段的补充场景。
