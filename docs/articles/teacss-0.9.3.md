# TeaCSS 0.9.3：Rust 引擎成了默认，以及一次更正

**结论。** TeaCSS 0.9.2 和 0.9.3 生成的 CSS 与 0.9.0 逐字节相同。用户会感觉到的变化是默认引擎换成了 Rust：不写 `engine` 选项的项目，从 0.9.2 起就用 Rust 引擎。在 20 000 个类、300 个文件的项目里：

- 开发服务器里保存一个文件，Rust 引擎要 70 ms，Tailwind CSS v4 要 323 ms；
- Vite 生产构建里，CSS 部分 Rust 引擎加 220 ms，Tailwind 加 558 ms。

这一轮还改了两处测法，并更正了之前的一个错误结论。

## 更正：TypeScript 引擎的开发服务器并没有在 0.9.3 变慢

上一版报告和本文的上一版说，0.9.3 让 TypeScript 引擎的开发服务器慢了约三分之一。这个结论是错的，原因在基准程序：

- 基准程序先创建插件，再调用 Vite 的 API，而 Vite 是在这个调用里面才设置 `NODE_ENV` 的。
- 0.9.2 及以前的 `@teacss/vite` 在插件创建时就读取 `NODE_ENV`，读到的是空值，于是开发服务器跑的是 TeaCSS 的「构建模式」。构建模式省掉了开发模式里的规则细节，所以更快。
- 用户在命令行里跑 `vite dev` 时，Vite 会在加载配置之前设好 `NODE_ENV`，所以用户拿到的一直是开发模式。
- 0.9.3 把读取推迟到了第一次钩子调用，这才和用户一致。

在 0.9.1 上只设 `NODE_ENV=development`，TypeScript 引擎的开发服务器就从 245 ms 变成 313 ms；Rust 引擎几乎不变（74 → 75 ms）。所以之前各份报告里，TypeScript 引擎的开发服务器数字都偏快，对 TeaCSS 有利。0.9.3 的数字才代表用户的真实体验。每份旧报告的审核里都补记了这一点。

这个问题是 teacss-ts 查出来的，我复现确认后改了测法。

## 两处测法的修订

两处都是为了让基准和用户在命令行里拿到的环境一致：

1. **编译缓存（协议修订 5）。** `vite`、`rsbuild` 和 `astro` 的命令行都会打开 Node 的编译缓存。基准以前谁都没开；现在所有 Node 构建和开发服务器都开。这一项是因为 teacss-ts 的 B5 让 TeaCSS 插件自己打开编译缓存：如果只有 TeaCSS 开，它就会占一个用户拿不到的便宜。
2. **`NODE_ENV`（协议修订 6）。** 构建时设为 `production`，开发服务器设为 `development`，和命令行一样。这修正了上面那个偏差，也让 Tailwind 的 PostCSS 插件在构建时做它本该做的生产优化。它的产出现在和 Tailwind 的 Vite 插件逐字节相同，构建也因此慢了约 140 ms：用户本来就要付这笔时间，以前的测法漏掉了。

Bun 没有这样的命令行，所以 Bun 组两样都不设。修订后，构建和开发服务器的数字不能直接和以前的报告比，引擎层的数字可以比。

## 20 000 个类、300 个文件

每格 30 次交替运行的中位数：

| 场景 | TeaCSS（Rust 引擎） | Tailwind CSS v4 | TeaCSS（TypeScript 引擎） |
| --- | --- | --- | --- |
| 在已经启动的进程里生成全部 CSS | 50 ms | 216 ms | 457 ms |
| 往运行中的引擎里加 10 个类 | 17 ms | 124 ms | 104 ms |
| 开发服务器里保存一个带 10 个新类的文件 | 70 ms | 323 ms | 299 ms |
| Vite 生产构建 | 399 ms | 737 ms | 998 ms |

各构建工具里，CSS 工具在基线之上加的时间：

| 构建工具 | 基线 | TeaCSS（Rust 引擎） | Tailwind CSS v4 |
| --- | --- | --- | --- |
| Vite | 179 ms | +220 ms | +558 ms |
| Vite + PostCSS | 179 ms | +274 ms | +760 ms |
| Rsbuild | 176 ms | +290 ms | +957 ms |
| Bun（Bun 运行时） | 72 ms | +150 ms | +334 ms |

117 组正面比较：Rust 引擎赢 107 组，Tailwind 赢 5 组，5 组无可测差异。

## 对 TeaCSS 仍然不利的地方

- **小项目构建。** 1 000 个类时，15 张构建表里：
  - Tailwind 在 5 张里可测地更快：Bun 的 3 张，领先 7 到 15 ms；Vite 与默认配置在 300 个文件时，领先 13 和 7 ms。
  - Rust 引擎在 5 张里可测地更快，领先 4 到 10 ms。
  - 5 张无可测差异，包括 PostCSS 的 3 张。
- **TypeScript 引擎的构建仍比 Tailwind 慢。** 45 组构建比较里 42 组更慢。
- **TypeScript 引擎占内存更多。** 生成一次后常驻 792 MB，0.9.1 时是 652 MB。这一项与 Vite 插件无关，原因还没查明。

## 公平性

方法与前几轮相同：

- 发布版、Node 24.14.1；
- 计时前逐类校验，78 000 个用例零差异；
- 所有对象逐轮随机交替，每格 30 次；
- 负载连续两分钟低于 2.4 才开始，各格负载份额 18% 到 27%；
- 构建计时到构建返回为止；
- 所有 Node 构建和开发服务器都使用命令行会设的编译缓存与 `NODE_ENV`。

每个 TeaCSS 对象都显式指定引擎，所以「TypeScript 引擎」那一列确实是 TypeScript 引擎。3 510 对样本里，两种引擎的产出逐字节相同。

限制不变：

- 只有一台 Apple M2 Max，Linux 交叉验证未跑；
- 只有生成的配对语料，社区语料还在等仓库清单；
- 本基准的作者也开发 TeaCSS。
