# TeaCSS 0.9.3：Rust 引擎成了默认，TypeScript 引擎的开发服务器慢了三分之一

**结论。** TeaCSS 0.9.2 和 0.9.3 生成的 CSS 与 0.9.0 逐字节相同。用户会感觉到的变化有两个：

- **默认引擎换成了 Rust。** 不写 `engine` 选项的项目，从 0.9.2 起就用 Rust 引擎。在 20 000 个类、300 个文件的项目里，开发服务器保存一个文件要 71 ms，Tailwind CSS v4 要 325 ms。
- **TypeScript 引擎的开发服务器变慢了。** 仍用 `engine: "ts"` 的项目，在 0.9.3 里保存一个文件从 231 ms 变成 307 ms，慢了约三分之一。0.9.2 还没有这个问题。

这也是第一轮按「协议修订 5」测的结果：所有 Node 构建和开发服务器都开着编译缓存，和用户在命令行里跑 `vite build`、`rsbuild build` 时一样。所以本轮的构建和开发服务器数字不能直接和以前的报告比，引擎层的数字可以比。

## 为什么改协议

teacss-ts 的 B5 让 TeaCSS 插件自己打开 Node 的编译缓存。检查后发现：

- `vite`、`rsbuild` 和 `astro` 的命令行本来就会打开这个缓存，不管项目用哪个 CSS 工具；
- 基准调用的是 `build()` API，以前谁都没开。

如果只有 TeaCSS 自己开，它在基准里就会占一个命令行用户拿不到的便宜。而且这个缓存作用于整个进程，连打包器本身也会变快，结果却算成「CSS 工具加的时间更少」。

所以协议改成每个 Node 对象都开，Tailwind 和基线也一样。Bun 没有这样的命令行，所以 Bun 组不开。改协议之前，B5 没有进入任何报告。

## 20 000 个类、300 个文件

每格 30 次交替运行的中位数：

| 场景 | TeaCSS（Rust 引擎） | Tailwind CSS v4 | TeaCSS（TypeScript 引擎） |
| --- | --- | --- | --- |
| 在已经启动的进程里生成全部 CSS | 51 ms | 220 ms | 461 ms |
| 往运行中的引擎里加 10 个类 | 16 ms | 124 ms | 103 ms |
| 开发服务器里保存一个带 10 个新类的文件 | 71 ms | 325 ms | 301 ms |
| Vite 生产构建 | 399 ms | 742 ms | 996 ms |
| 其中 CSS 部分（减去 178 ms 的基线） | 222 ms | 564 ms | 818 ms |

各构建工具里，CSS 工具在基线之上加的时间：

| 构建工具 | 基线 | TeaCSS（Rust 引擎） | Tailwind CSS v4 |
| --- | --- | --- | --- |
| Vite | 178 ms | +222 ms | +564 ms |
| Rsbuild | 176 ms | +292 ms | +972 ms |
| Bun（Bun 运行时） | 72 ms | +151 ms | +334 ms |

117 组正面比较：Rust 引擎赢 107 组，Tailwind 赢 8 组，2 组无可测差异。0.9.1 时是 102、8、7。

## TypeScript 引擎变慢是怎么确认的

本轮的数字是 301 ms，上一轮 0.9.1 是 228 ms。两轮的协议不同，所以单看这两个数还不能下结论，又做了三项核对：

- **对照没动。** 同一轮里，Rust 引擎的开发服务器（70.1 → 70.8 ms）和 Tailwind 的（320.6 → 324.8 ms）都没有变。编译缓存在开发服务器启动前就打开了，不影响计时的那一段。
- **同一套协议下并排测。** 0.9.1 和 0.9.3 交替运行两次，各 20 次：231 ms 对 307 ms。在 5 000 个类时是 94 对 111 ms。
- **找到是哪个版本。** 0.9.2 和 0.9.3 交替：235 ms 对 315 ms。0.9.3 唯一的改动是 B6：让 `@teacss/vite` 的入口延迟加载。

TypeScript 引擎本身生成 CSS 的速度没变（461 ms），所以慢在开发服务器这条路径上。这个问题已经交给 teacss-ts；修好后会先在未发布通道里测。

## 对 TeaCSS 仍然不利的地方

- **小项目构建。** 1 000 个类时，15 张构建表里：
  - Tailwind 在 8 张里可测地更快，领先 7 到 15 ms，主要在 PostCSS 和 Bun 两条路径上；
  - Rust 引擎在 5 张里可测地更快，领先 5 到 10 ms；
  - 2 张无可测差异。
- **TypeScript 引擎的构建仍比 Tailwind 慢。** 45 组构建比较里 42 组更慢。
- **P14 测不出来。** teacss-rs 的 P14 让类名提取在引擎层快了约 4 ms，但在端到端的构建和开发服务器里没有可测差异。

## 公平性

方法与前几轮相同：

- 发布版、Node 24.14.1；
- 计时前逐类校验，78 000 个用例零差异；
- 所有对象逐轮随机交替，每格 30 次；
- 负载连续两分钟低于 2.4 才开始，各格负载份额 17% 到 25%；
- 构建计时到构建返回为止；
- 所有 Node 构建和开发服务器都开编译缓存。

每个 TeaCSS 对象都显式指定引擎，所以「TypeScript 引擎」那一列确实是 TypeScript 引擎：没有一个样本加载了 Rust 的原生文件。3 510 对样本里，两种引擎的产出逐字节相同。

限制不变：

- 只有一台 Apple M2 Max，Linux 交叉验证未跑；
- 只有生成的配对语料，社区语料还在等仓库清单；
- 本基准的作者也开发 TeaCSS。
